# Round 5 実装メモ

対象は [round5_sampling_adaptive.cpp](round5_sampling_adaptive.cpp)。紙の不透明部分を列順の先頭区間とする既存構造を維持し、紙の長さ配分と、公開商品だけを使う移動費用学習を改善した。以下は候補段階の記録であり、`main.cpp` 反映後の最終検証結果は別途追記する。

## 紙の配分と学習

全表示を表現できる65枚の基本構成から始め、残り127枚を長い区間から追加する。各長さへの追加要求数を従来の一律6枚から、**長さ53以上は8枚、それ未満は4枚**へ変更した。実際の追加枚数は残り枚数と異なる模様の数で制限する。同じ長さの枚数が増えるため、初期学習のtrie DP配列も17要素へ拡張した。

初期設計は表示に必要な紙数を目的に4パス学習する。その後、内部で生成した注文列から重ね順を採取し、各状態から各商品の表示へ到達する厳密な移動費用を使って、長さ64から43まで各紙の色を更新する。公開256商品を毎反復シャッフルし、各商品を同じ回数だけ学習対象にする。実注文を先読みする処理はない。

## 数学的に等価な高速化

ここで `F[j][h]` は先頭 `j` 窓までの前向き費用、`B[l][h]` は残りの費用、`h` は選択した紙の元の位置の最大値に1を足した値とする。`C_l(h)` は元の順序の先頭 `h` 枚のうち、長さが `l` 以上の紙の枚数。

1. **距離表の圧縮。** 正則化なしの移動費用は、重複しない移動対象紙の計数であり、有限値は紙数192以下となる。`F/B/route` を8ビット、到達不能値を255にした。`F` は有限な `(h,費用)` だけを16ビットに詰め、元の列挙順を維持する。`B` は参照される長さ43～64だけ保存する。正則化や負の報酬を辺費用へ加える場合、この上界と表現は再検討が必要。

2. **同じ長さの紙をまとめた後向きDP。** 長さ `L>l`、位置 `q>=h` の候補の費用は、次式となる。

   ```text
   C_L(q) + B[L][q+1] - C_L(h) + [D(q) > D(h)]
   D(h) = C_(l+1)(h) - C_L(h)
   ```

   `h` を降順に走査し、候補を `D(q)=D(h)` と `D(q)>D(h)` の2群に分けて最小値を保持する。`q<h` の候補は共通の `B[L][h]` となる。同じ長さの紙を個別に全 `h` へ展開する処理を、長さごとの走査に置き換えた。未到達候補の仮の最小値には510を使い、`C_L(h)` を引いた後に到達可能と誤認しないようにしている。

3. **ある長さを使わない経路の再利用。** 長さ `L` の紙を確定した直後、各辺 `j→L` の `F+移動費用+B[L]` を、飛び越える全境界 `j<l<L` の `bypass[l]` へ反映する。長さを降順に更新するため、後続の短い紙の更新で、この辺に使った `F[j]` と `B[L]` は変わらない。各境界で長い紙を再走査する必要がなくなった。辺の費用は既存の `route` の累積最小値を取る前に保存して再利用する。

4. **trieへの加点を変化点に限定。** `route` の累積最小値が更新される深さと費用だけを保存する。値が同じ深さでは利得差分も0なので、全64深さへの加点を省いても、各葉の合計利得と選択時の同点処理は変わらない。

これらは同じ学習状態・反復数についてDP値と選択を保つ変更である。時間制限で学習を打ち切る設定では、高速化によって完了する更新数が変わるため、最終出力まで一致するとは限らない。

## 適応的な反復数と時間ガード

問題の注文数 `R=1024` と区別し、学習反復数を `m` とする。内部の準備注文128件の後、最初の4反復（1024件）の状態採取に使ったCPU時間を測る。1反復の実測時間を `t`、採取開始までのCPU時間を `t0` とし、次の見積もり以下で最大の `m∈{8,12,16,24,32}` を選ぶ。

```text
見積もり反復数 = (1.65 - t0) / (4.0 * max(t, 10^-6))
```

係数4.0は、採取後のDPと色更新も含む計算量の実測に基づく安全側の推定。候補がすべて見積もりを上回る場合も最低8反復とし、後述の時間ガードで打ち切る。上限32は改善幅とメモリ使用量から決めた。内部注文列の先頭部分をそのまま使うため、同じ `m` の固定設定と学習データは一致する。

- 起点は事前情報を読み終えた直後の `clock()`。初期設計は絶対CPU時間0.5秒、移動費用学習は1.65秒を目安に終了する。
- 初期設計と色更新は長さごとの境界、状態採取と前向きDPは64件ごとに時刻を確認する。開始済みの処理を途中で破棄する厳密な期限ではない。
- 初期設計の各更新は全公開商品の表現可能性を確認する。後段も各公開商品を含む学習状態で有限経路を確認してから色を変更するため、途中終了時には直前の有効な設計を使用できる。後段の状態採取・前向きDP中に終了した場合は、色更新前の設計を使用する。
- 最終教師状態の再生成、実際の1024注文、I/Oは1.65秒の学習ガードの外にある。計測はCPU時間であり、ローカルの対話待ちを含む経過時間とは異なる。係数と定期確認だけで任意の環境の2秒以内を保証するものではなく、余裕を残して実測確認する。

## 候補段階の検証

圧縮前後について、seed0の固定16/32反復は出力全文一致、先頭10件はケースごとのスコア一致を確認した。配分境界57・32反復でも、集約・再利用・疎なtrie加点を統合した版の先頭10件が元の版と各件一致した。`SAMPLING_CHECK_B` 付きの検証版では、seed0・8反復の全 `B` セルと `bypass` を元の漸化式で再計算して照合し、出力全文も一致した。

固定32反復・seed0のRSSは圧縮前555164 KiBから圧縮後148768 KiBへ減少した。全高速化後は配分境界57・同ケースで159080 KiB、適応版の配分境界53・seed0は146208 KiBだった。64反復は改善せずメモリも増えるため採用していない。
