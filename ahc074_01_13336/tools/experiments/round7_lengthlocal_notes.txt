Round 7: individual prefix-length +/-1 search (not adopted)
=========================================================

Experiment files only; main.cpp/a.out/pahcer outputs are unchanged. Parent
later found the related length-neighbor experiment in round5_notes.md; this
round therefore stops after the requested 20-pass diagnostic rather than
extending an overlapping search.

Search:
1. Start from the standard cutoff53, fixed-R8 learned dictionary.
2. Generate reachable internal states using only public A, the ordinary
   teacher and online policy, with 128 warmup queries followed by either
   64 or 256 sampled public target/state pairs.
3. Enumerate each paper shortened by one (truncate color), or extended by
   one with new bit 0/1. Keep 192 papers. Paper IDs need not remain sorted
   by length; all downstream graph/operation routines use explicit length.
4. First require all 256 products to remain representable. For each target,
   scan lengths upward, advancing the covered prefix whenever any paper
   of that length agrees with the uncovered interval. Only the two changed
   length levels need their minimum-compatible-start recomputed.
5. Evaluate the exact shortest legal movement cost of every feasible
   candidate on the captured state/target pairs. Accept the best strict
   improvement, then regenerate states before the next pass.

Evaluator speedup:
A one-step length change modifies the count of papers of length >=threshold
at only one threshold. For a fixed snapshot, the count difference on source
positions [h,q) is +/-1 precisely when the modified paper lies in that
interval. All other count thresholds remain unchanged. Target-compatible
candidate lists are updated only for the changed paper and restored after
scoring. This gives the same exact shortest distance as PrefixDP without
rebuilding all count tables for every candidate.

Validation:
LENGTHLOCAL_CHECK reconstructs the snapshot's permutation and compares each
candidate/sample distance against a fresh original PrefixDP. Seed0, one
pass/two samples checked all feasible candidates with no mismatch.
All official tester results had E=0 and satisfied the per-query move limit.

Results: public seeds0..2, diagnostic CPU deadlines100, at most2 workers.
  Baseline R8: 13276.6667 (13343,13444,13043)
  5 passes, 64 samples:  13436.3333 (+159.67), mean CPU1.867s
  5 passes, 256 samples: 13268.6667 (13300,13413,13093), delta-8.00,
                         mean/max CPU3.160/3.393s
 20 passes, 256 samples: 13330.6667 (13286,13613,13093), delta+54.00,
                         mean/max CPU10.693/11.500s

About394..404 candidate mutations per pass passed the representation check.
Most selected changes were among lengths53..63; some length44..52 changes
also became possible. The fixed-state objective improves each accepted
step, but the cost after resimulating new states does not decrease
monotonically. No large gain was demonstrated, and the tiny five-pass
improvement is insufficient to justify runtime work or wider evaluation.
No production two-second variant was integrated.

Files/API:
round7_lengthlocal_build.py -> round7_lengthlocal.cpp
round7_lengthlocal.h: namespace Round7LengthLocal
  capture(A,papers,count) -> vector<Snapshot>
  Evaluator(A,papers) keeps papers by reference and target candidate lists
  evaluate(snapshots,changed,replacement) scores a single length mutation
  update_candidate(k,old,new) updates only target compatibility
  distance(snapshot,changed,threshold,sign) evaluates the exact cost

The same evaluator was shared with the separate source-product-swap
experiment. For color-only changes, count correction is zero. The provided
feasible() helper assumes distinct old/new lengths and should not be used
for same-length recoloring or a two-paper swap.
