# 初期辞書学習の等価高速化

前半はDP再利用のみの [round6_initial_fast.cpp](round6_initial_fast.cpp) の記録。後述のPatricia trie圧縮まで統合した最終候補は **[round6_triefast_final.cpp](round6_triefast_final.cpp)**。紙の配分、目的関数、選択順と同点処理を保ち、初期学習と厳密移動費用学習を高速化した。この担当から `main.cpp` は変更していない。

## 等価性の根拠

各パスで紙の長さを降順に処理する。長さ `l` の更新時に参照する値について、次が成り立つ。

- 前向き費用 `F[j]`（`j<l`）には、長さ `l` 以上の紙が寄与しない。既に更新した紙はすべて長さ `l` より大きいため、パス開始時の値をそのまま使える。
- 後向き費用 `B[l]` は長さ `l` より大きい紙だけに依存する。その長さの紙は既に確定しているため、上の長さから辺を流すことで一度だけ計算できる。
- 長さ `l` を使わない経路は、ある辺 `j→L`（`j<l<L`）でその境界を飛び越える。長さ `L` の紙を確定した際に、`F[j]+1+B[L]` を飛び越える境界の `cross[l]` へ配れば、毎回すべての長い紙を調べた場合と同じ最小値になる。

このため、前向きDPの全計算は各パスの開始時だけ行い、後向きDPと `cross` は確定した各長さから更新する。実装上は既存の `distances()` をパス開始時に呼び、後向き配列を初期化して流し直すため、開始時の後向き計算が1回分重複するが、各長さでの全再計算はなくなる。

新しい紙を追加できない長さ、紙のない長さ、trieの候補が不成立の長さ、表現可能性チェックで候補を却下した長さでも、**変更されなかった紙から後向きDPと `cross` を更新してから次へ進む**。この処理を飛ばすと下位のDPが不完全になるため、各 `continue` で明示的に扱った。

初期backbone学習では、同じ長さの固定紙による経路も従来どおり `bypass` に含める。全紙再学習では同じ長さの紙をすべて置き換えるので、`cross[l]` のみがその長さを避ける経路になる。

## 数値・出力の検証

`INITIAL_DP_CHECK` を有効にすると、各長さの学習前に元の `distances()` を再実行し、実際に参照する以下の値をすべて照合する。

- 全256商品について `F[j<l]`。
- 全256商品について `B[j>=l]`。
- 元の長い紙の全走査で計算した `bypass` と `cross[l]`。

照合後は高速版の配列を復元する。まだ使わない `F[j>=l]` と、未完成の `B[j<l]` は一致の対象ではない。

時間打ち切りを無効化した固定条件で、seed0～4を検証した。

| 条件 | 確認結果 |
| --- | --- |
| 固定8反復、旧版対高速版 | 5件すべて出力全文一致 |
| 固定32反復、旧版対高速版 | 5件すべて出力全文一致 |
| 固定8反復、参照照合有効版 | 5件すべて数値assert通過、出力全文一致 |
| 初期CPU計測用の再実行、固定8反復 | 5件すべて出力全文一致 |

出力全文には192枚の設計と1024注文の全操作列を含む。比較結果とSHA-256は [round6_initial_compare.json](round6_initial_compare.json) に保存した。診断用のソースは [round6_initial_reference.cpp](round6_initial_reference.cpp) と [round6_initial_fast_diag.cpp](round6_initial_fast_diag.cpp)、生成手順は [round6_initial_fast_build.py](round6_initial_fast_build.py) を参照。

## CPU時間

初期学習終了直後の `clock()` を追加して、旧版と高速版を1プロセスずつ順番に動かした。以下はローカル5seedの平均であり、AtCoderでの測定値ではない。

| 測定対象 | 旧版 | 高速版 |
| --- | ---: | ---: |
| 初期学習、seed0～4 | 0.373639秒 | 0.325594秒 |
| 初期学習、seed1～4のみ | 0.339421秒 | 0.319935秒 |
| 固定8反復を含む全処理、seed0～4 | 0.849679秒 | 0.750026秒 |

seed0では旧版の初期時間だけが0.510510秒と大きく、初回起動や測定時の状態の影響を除けない。短縮幅を一律に約0.1秒と断定せず、初期処理単独で約0.02～0.05秒の差が観測されたと扱う。

先に行った3workerの比較では、固定8反復の全体平均が1.672982→1.442122秒、固定32反復が3.688750→3.550530秒だった。並列負荷と実行時期の差があるため、この差を単体の高速化幅とはみなさない。詳細は [round6_initial_timing.json](round6_initial_timing.json) に保存した。

## 追加：共有Patricia trieによる主要な短縮

DP再利用後に各段階を測ると、seed0の初期処理0.396秒に対し、backboneのtrie構築が0.0485秒、再学習のtrie構築が0.2508秒を占めた。trie DP自体は合計0.0205秒、commitと後向き更新は合計0.0049秒だった。全商品・全深さをたどり、大きいDP配列を持つノードを繰り返し生成する部分が主な負担だった。

各長さのsuffix trieの構造は公開商品と列順だけで決まり、紙の色の更新や学習パスには依存しない。そこで、初期backbone、初期再学習、後段の厳密学習で **同じ構造と商品・深さからノードへの対応表を共有**した。公開商品列が変わった場合はキャッシュを破棄する。

さらに、子が1つだけのノードを圧縮した。元の各unaryノードの重みを、その先の最初の分岐ノードまたは葉へ加える。どの葉集合を選んでも、unaryノードが選択される条件はその唯一の子孫部分木から1枚以上選ぶ条件と同じなので、重みの合計と各枚数のDP値は変わらない。0枚の費用は従来どおり0にする。ノード数は各長さで最大 `2P−1=511` となる。

分岐と葉は、元のvectorに現れた順番を保って採番する。これにより親が子より先に現れ、左右の枝順と葉の走査順も保持される。初期trie DPの同点選択と、厳密学習で最大重みが同じ場合に最初の葉を選ぶ動作を保つ。深さごとの重み差分は、対応表を介して圧縮先ノードへ加える。

共有実装は [round6_trie_topology.h](round6_trie_topology.h)。最終ソースには定義を1回だけ展開してあり、外部ファイルに依存しない。追加メモリは主に各商品・深さの対応表で、距離表のメモリを大きく増やさずに共有できる。

### 統合版の照合

[round6_triefast_compare.json](round6_triefast_compare.json) に記録した比較で、固定8反復・固定32反復それぞれseed0～4の **全stdoutが元のmain由来版と一致**した。

固定8反復の5件では、以下を同時に有効にしてすべて通過した。

- `INITIAL_DP_CHECK`: 前述の前向き・後向き・境界を飛び越える経路の参照照合。
- `INITIAL_TRIE_CHECK`: 同じ重み差分を非圧縮trieにも加え、枚数0～上限のroot DP値と、有効な各枚数のcollect結果の葉sample列を比較。
- `EXACT_TRIE_CHECK`: 非圧縮trieとの累積重み、最良葉の重みとsampleを比較。
- `SAMPLING_CHECK_B`: 厳密学習の後向き距離とbypassを元の漸化式で比較。
