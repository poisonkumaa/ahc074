## 現在の方式

- 全64窓をまとめて扱う。窓の並びを隣接窓の一致度で焼きなまし、各列の白黒反転も選ぶ。
- 各紙は並べ替えた窓の先頭からある長さまで不透明、残りは穴。可視紙の長さは上から増える。
- 最初に全バーコードを表示可能な65枚を用意し、残る127枚を長い紙へ配る。公開256商品の必要区間数を減らすようtrie上で色を学習し、その後は最初の65枚も含めて全紙を4巡再学習する。更新ごとに全商品の到達可能性を保つ。
- 注文ごとに「確定窓数・選択紙の元位置の最大値」のDPで最小操作数を求める。同じ操作数なら直近の注文でも使われやすい紙を優先する。
- 合法な最短操作の中から、直近64個の到達状態に対する必須取り出し回数が小さくなる操作を選ぶ。紙ごとの64bit集合の和集合で、同時に選ばれる紙の相関を評価する。初期集合だけは公開商品から内部生成した注文で作る。
- 学習をCPU 0.75秒で打ち切る。更新単位の途中では止めず、打切り後も全商品を表示できる。固定配列・DP領域再利用・前後距離による学習計算の省略で時間を短縮した。

紙の設計に使う入力は最初の256商品のみ。実注文は回答をflushしてから1つずつ読む。オンラインの64状態バッファは処理済み注文だけで更新する。
提出ファイルは単独でコンパイルでき、外部ファイル・引数・環境変数に依存しない。

## 旧4窓ブロック方式の記録

以下は平均26,235.22点だった段階の記録。`validation_26235.json` に当時の100ケース結果を保存している。

前版は平均26,492.83点、元の基準実装は平均32,770.00点。前版のケース別結果は `validation_26492.json`、ソースは `main_26492.cpp` に保存。

旧方式:

- 64窓を4窓ずつに分け、各ブロックを6枚の紙で制御する。残る96枚は全て穴。
- 6枚の720通りの重ね順について、見えている紙だけを動かす有向グラフを構築する。
- 商品分布を使った相対価値反復と逆向きDijkstraで操作を決める。
- 固定方策の到達状態を集め、商品分布に対する定常分布から平均操作数を評価する。
- その平均操作数を基準に、窓の組合せ・順番・白黒反転を同時に焼きなまし法で探索する。実際の注文は先読みしない。
- 最大10万回、または探索のCPU時間0.95秒で打ち切る。最良の組合せを保存し、最後に各ブロックの方策を再計算する。
- 全ブロックを連続した位置に保つため、挿入位置は `6 * group + local_position`。

`baseline.cpp` は元の実装。`block_main.cpp` は平均26,492.83点だった前版のコピー。`pair_main.cpp` は2窓6枚の前段階の候補（seed 0: 32,056）。`build_direct.py` で最新方式の提出用ソースを生成できる。

試した別方式:

- ランダムな多窓模様と不一致数による貪欲法: 局所解と紙の取り出し費用が大きく、改善せず。
- 3商品の共通部分を紙にし、担当商品の交換で共通範囲を拡大: seed 0で表現枚数は平均5.61だが、256商品のうち30商品が表現不能。取り出す操作も別途必要なので、この枚数を操作数として扱ってはいけない。
- 4商品共有: 表現不能2商品、表現枚数平均8.20。
- 8商品共有: 表現不能0商品、表現枚数平均17.29。実操作探索は不十分。
- ビーム探索: 表示が変わらない操作も必要。単なる不一致数では探索が止まる。最初の正しい色までにある誤色の枚数を評価に足しても、現在のブロック方式に及ばない。
- 小ブロックの紙模様の焼きなまし: 4窓6枚で一様分布時の平均約1.67597操作を発見し、現在の候補に採用。
- 複数ブロックの紙を結合した追加紙: 下に残る同じ模様の紙が操作を妨げ、貪欲探索では悪化。`compound.cpp` に保存。
- `check_cutoff.py` で探索を即座に打ち切るケースも公式テスタで検証し、誤り0・有効な操作列を確認した。
