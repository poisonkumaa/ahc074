# Round 5 探索記録

前回版はローカル100seed平均13,530.22。ユーザー報告のAtCoder結果は50ケース合計678,704、実行時間613ms。制限2秒。今回は紙の長さ配分・再学習量・高速化・オンライン方策を並行探索した。実際の将来注文は評価用テスタだけが保持し、解答プログラムの学習には渡していない。

## 採用

追加紙の配分を「長さ53以上8枚、以下4枚」に変更。再学習は公開256商品ごとに8～32通りの内部状態を使う。有限状態だけを保存する前方DP、同じ長さを集約した後方DP、長さをまたぐ経路の再利用、trie重みの差分化によって計算を削減した。高速化の根拠は `round5_implementation_notes.md`。

最終版は `round5_sampling_adaptive.cpp` と同一。SHA-256は `12f6ae6570b5d322e73a2e169e7f05d7ce5058a775fd65892f7b5da6f4209142`。初期学習CPU 0.5秒、再学習開始から1.65秒の期限。最初の4反復の所要時間から8/12/16/24/32の学習量を選ぶ。最終的な結果は `README.md` と `validation.json`、`round5_final_validation.json` に記録する。

## 不採用の試行

- **2設計の比較。** 通常列順と32列回転した列順を各8状態で学習。内部状態32個に対し全255次商品を評価して設計を選択。平均13,320.16、最大CPU 2.283秒。単一32状態との差が3.17点しかなく、追加時間と制御の複雑さから不採用。単独の回転設計は13,366.34。ファイル `round5_portfolio_100_32_8_results.json`。
- **同じ長さの紙を複数回再学習。** 従来配分・8状態・2巡は13,518.64。改良配分57・32状態へ組み込むと13,382.05で、1巡の13,372.93より悪化。採用せず。`round5_profile_local_100_32_1_43_results.json` はタイマーを緩め忘れた条件なので、固定条件比較から除外する。正しい比較は `_diagnostic_` 付き。
- **利用頻度で再学習費用を補正。** 合法操作数の128倍から紙の選択頻度に応じた報酬を引く。強さ64・従来配分・8状態は13,503.78。強い補正は悪化。8bitの非負費用を使う高速実装とも両立に追加修正が必要なため不採用。`round5_price_100_64_8_results.json`。
- **紙の長さ±1。** 色候補とともに変更し、別の内部状態集合で確認。10seed段階の小さな改善は評価状態を増やすと失われた。
- **隣接窓と紙模様の同時変更。** 1箇所の窓交換の前後DPを再利用し、境界紙の色も再学習。参照DPとの数値一致は確認できたが、10seed平均13,284.9で同条件の変更なし13,265.5より悪い。`round5_design_joint_p1_r8_c53_u8_l4_10_x3_64.json`。
- **オンライン方策。** 最小手数と+1手のゴール、頻度最大/最小・記録数最大/最小の候補、全255次商品の期待値、2段の先読み、追加移動、履歴の定期再学習を比較。少数seedの微小改善に対して計算が重く、最終版の方策は変更していない。`round5_policy*.json`。

複数設計の各実注文スコアの最小値を取った参考値も算出したが、これはオフラインの比較用である。実装は公開商品の内部評価だけで選び、実注文を見て設計を切り替えない。

## 再開時の注意

- `main.cpp` と `a.out` は最終版。古い `install_round4.py` 等を再実行しない。
- `round5_sampling_*_build.py` は高速化を順に適用する作成スクリプト。診断版・固定条件版・適応版の区別に注意。
- 時間制限付きの適応版は実行負荷により紙の初期再学習回数と状態数が変わる。同一ソースでもスコアは完全固定ではない。
- 現行圧縮は正則化0・非負の移動費用が前提。報酬を学習の辺費用に入れる際は型と上界を変更する必要がある。
- 平均約6,554点という当初の目標には届いていない。今回の改善は約1～2%で、現在の接頭辞設計の継続的な改良によるもの。
