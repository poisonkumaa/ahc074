# Full-graph offspring matching

`design_candidate.cpp` is generated by `design_make.py` from the frozen
`main_baseline.cpp` SHA256
`2A36BD6C8D4944AA61068D4AC85FB7773DD1F1FF59970BC84CF37512CD3278E7`.
The production source is unchanged. Implementation: `design_matching.inc`.

The new baseline already crosses two fully constructed parent designs that share
one core map. Its `merge_matching` selects one parent's matching in each connected
component of the two matchings' union, using a DP to retain the required number
of pairs. It cannot introduce an edge absent from both parents.

This experiment changes only the optional eighth candidate's starting matching:

- `DESIGN_MATCHING=0` (default): original crossover, unchanged.
- `DESIGN_MATCHING=1`: consider every pair whose stored core cost is finite and
  whose literal core constraints form a DAG in both parent layouts.

The new objective uses the same model as `matched_items`: each group's cheapest
anchor combines parent bank load, paired-paper count, and a color-demand-based
prefix repair estimate. Prices are averaged over both parents. A pair's core
price is added once; the two corresponding singleton prices are subtracted, so
the fixed-cardinality matching also accounts for which products remain single.

Search starts from the original crossover and both parent matchings. It performs
two-edge or matched-to-single exchanges, plus three-edge alternating path/cycle
exchanges, then greedy descent. Only the best complete matching is returned.
The original first seven candidates, core map, selected parent pair, child layout
rebuild, and synthetic race remain unchanged. No actual future requests are read.

Defaults: `DESIGN_MATCHING_ITERS=60000`, `DESIGN_MATCHING_CPU=.04` local time units,
`DESIGN_MATCHING_END=NOV8_LAYOUT_END-.02`. A pricing timeout returns the original
crossover. A search timeout returns the best fully valid matching found. Every
returning change is checked for disjoint product ownership, exactly `64+B` pairs,
literal DAG feasibility, and nonincreasing proxy cost. The parent constructors
rebuild main rows and all pair metadata afterward.

`DESIGN_MATCHING` diagnostics report edge count, pair count, changed pairs,
edges absent from both parents, proxy before/after, iterations, and elapsed CPU.
The proxy freezes parent loads and demand while pairing changes, so its improvement
does not imply an actual operation-count improvement. An independent read-only
review found no mutation/cardinality/metadata defect. This agent did not compile
or benchmark the variant; measurements are coordinated by the root agent.
