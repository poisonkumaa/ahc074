# Route candidates for the latest checkpoint

All sources are generated from `main_baseline.cpp` (SHA256 `407A5355D6A75BBE07BD332A265FCB694B532DC7F35DE0DEE465006BF136A7E7`). They do not modify `main.cpp`. Compilation and benchmarks are owned by the root agent so timing measurements remain isolated.

- `route_noop.cpp`: exact final replay removes no-op moves introduced by the last shelf adjustments. `FINAL_NOOP=1` (default), `0` disables. The parent measured zero saved moves in six initial cases; not an established improvement.
- `route_triple.cpp`: extends `loan_tail` from two to three complementary donors. A beam of at most 12 upper pairs is expanded by one lower donor. Each lower donor's wrong ink must be occluded by an upper donor. Six execution orders are replayed with visibility checks, final barcode validation, the existing reusable-state reconstruction, and the existing future-cost veto. `TAIL_TRIPLE=0` is the baseline control, `1` enables. `TAIL_TRIPLE_CPU=.04` is the default extra-search budget in local experiment units (0.024 native CPU seconds on Linux). The budget is checked between batches and trials, so one batch may overshoot it; the general deadline is also checked. Disabled mode preserves the original one/two-donor execution order and anchors.
- `route_lis.cpp`: replaces the repeated-paper-only gate of the existing `fixed_deck` call with a necessary LIS bound for unique-paper routes. It can discover an alternative set of moved papers (ABCÅ®BCAÅ®CAB uses two distinct moves while moving C to the front uses one). `DECK_LIS=1` default, `0` control. The parent has a more comprehensive independently implemented final reconstruction candidate; this file is only a gate-change ablation.
- `route_depth.cpp`: preserves up to two distinct terminal decks for the same moved-paper sequence in the eight-entry route reservoir. Keys include insertion depths, while a separate paper-only group key enforces the cap; identical physical terminal decks are merged. Initial-route filtering uses the same depth-sensitive hash. Existing second/third alternatives retain their paper-sequence diversity. `DEPTH_PORTFOLIO=1` default, `0` preserves baseline selection logic.

The triple and depth variants are substantive search changes, not card-count tuning. No favorable score claim is made before the parent's paired benchmarks.

## Sampled design-race calibration

`route_race.cpp` addresses a structural evaluation mismatch: design candidates are raced with the cheap policy-0 router, while live queries also use relaxed trace shortening. Every eighth synthetic request supplies a matched shadow experiment for all active candidates. Each shadow starts from that candidate's actual raw trace, runs `nov5_relaxed_trace::optimize`, and restores the raw terminal state; later raw requests therefore retain their original state distribution. Only fully completed candidate batches contribute data. All inputs come from the disclosed catalog and the existing independent synthetic order sequence.

The corrected cumulative estimate is `raw_score - weight * query_count * saved_sum / (sample_count + prior)`. Defaults are `RACE_SHORT_WEIGHT=1`, `RACE_SHORT_STRIDE=8`, `RACE_SHORT_PRIOR=8`. The elimination threshold combines the original raw pair-difference variance with the measured paired shortening variance, scaled to cumulative score units. The same corrected estimate is used for leader choice and final selection. `RACE_SHORT_WEIGHT=0` disables shadow work and score correction.

Additional work is capped by `RACE_SHORT_BUDGET=.10` local experiment units (0.06 native CPU seconds on Linux) and the original `NOV8_SELECT_END` deadline. The global relaxed-trace and routing counters are saved and restored around each shadow batch, preserving the live relaxation quota. Stderr `RACE_SHORT` reports batch completion, aborts, CPU time, and per-candidate raw/sample/saving/adjusted values. The parent owns performance testing; no improvement claim is implied here.
