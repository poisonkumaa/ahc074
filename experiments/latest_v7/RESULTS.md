# 最新 main.cpp からの改善実験

2026-11-07。**将来コスト評価の18係数を再学習した版を採用し、`main.cpp` に反映した。** 学習に使っていない通常実行60ケースで、平均操作数は10624.050から10622.117へ減少した。合計116手の改善、全ケース `E=0`。差は小さく、全入力での優位や10000手達成を保証する結果ではない。

## 比較基準と調べた範囲

今回ユーザーが更新したコードを `main_baseline.cpp` に保存した。基準 SHA256 は次のとおり。

```text

```

比較開始時の `main.cpp` も同じ SHA256。以前の `v25_v6` の基準とは異なる。冒頭の古いバージョンコメントだけで判断せず、最新の貸出カードの返却色、棚先頭の重み、`ordinary54`・`shelf58` の挿入位置調整を含めて読んだ。採用後の SHA256 は末尾に記載する。

役割ごとのカード枚数は変更せず、次を中心に実験した。

- 操作列短縮の探索範囲、同じカード列で挿入先が異なる候補の保持。
- 将来コスト評価と、評価後に実行される棚並べ替えとの整合。
- 既存の棚 MDP の終端状態比較への利用。
- 設計候補を選ぶ際の、簡易ルータと本番短縮処理の評価差。
- 同じソート結果の再利用による探索時間の削減。
- 最終注文で不要になる「次の注文にも使える山札」の制約の除去。

## 評価条件と制約

比較は同じローカル Linux 環境のバイナリで行い、`improve_eval/bench.py` で出力された全操作の可視性・移動・最終表示を独立に再生した。表のスコアは小さいほど良い。全ケースで誤答数 `E=0` なので、表の平均スコアは平均操作数 `T` と一致する。

CPU 時間はソルバの `BUDGET ... cpu=`、wall はハーネスの経過時間。これらはローカル実測であり、AtCoder 上での時間保証ではない。比較は逐次実行・実行順交代で行うが、時間制限による探索打ち切りや実行時間の揺れで、設計の選択・探索量が変わる場合がある。

**固定設計の実験と、設計から実行する実験を区別する。**

- 固定設計では `beam_v1/fixtures` にある過去のカタログ由来の設計を使用し、設計生成を省略する。未来の実注文は含まれない。
- 固定設計の設定は `NOV8_ROUTE_END=30`、`NOV8_RELAX_END=30`、`NOV8_SHORT_END=30`、`NOV5_RELAX_BUDGET=10`。通常の2秒制約の検証ではなく、同じ設計に対するルーティング差を調べる研究条件である。
- 旧 `AHC074_LAYOUT_V1` 形式には、最新 `HeadSample` の `return_color[2]` が保存されない。読み込み後はゼロのままであり、最新コードが生成した履歴を完全には再現しない。したがって固定設計での改善だけで採用せず、最新の設計生成を含む通常実行で再検証する。
- 通常実行は上記の延長設定を付けず、事前設計から全1024注文まで実行する。
- `normal1_hold20.json` の 400–419 は `design_v3/generate_validation.py` による独立なローカル入力番号であり、公式ジェネレータの seed 番号ではない。
