No production source was changed. No compilation or benchmark was run by this agent.

## Finding

The original race shuffles all 256 products and visits each once per block. Its
`order_adjustment` uses the conditional expectation for a different distribution:
uniform over every product except the previous one. After the first position in a
block, products already visited have probability zero, so that control need not
have conditional mean zero. The shuffled stream also changes the deck-state
distribution relative to the actual IID requests with immediate repeats excluded.

Plain IID sampling was already tested in `improve_eval`, without convincing gains.
This experiment therefore isolates the conditional-control correction and tries
fitting the correction coefficients to paired candidate differences.

## Modes

| `SEL4_MODE` | Synthetic stream | Control coefficients |
|---|---|---|
| 0 (default) | Original shuffled blocks | Original function, unchanged |
| 1 | Original shuffled blocks | Exact remaining-product expectation, fixed |
| 2 | Uniform excluding previous | Exact 255-product expectation, fixed |
| 3 | Uniform excluding previous | Exact expectation, coefficients fitted online |
| 4 | Original shuffled blocks | Exact remaining-product expectation, fitted online |

Fixed coefficients are the original `.9, .54, .9` for retrieval depth, uncovered
prefix mismatches, and cached exact core distance. The expected and observed
feature use the same literal calculation. In particular, a missing distance table
contributes zero to both, rather than relying on a separately cached future value.

The three-dimensional ridge fit centers each observation across live candidates,
so it targets noise in candidate *differences*. Its statistics update only after
all candidates finish the current query; coefficients update before a later draw.
Thus coefficient learning does not use the observation currently being scored.
Defaults: `SEL4_RIDGE=32`, `SEL4_COEF_MAX=2`; first update after 32 observations,
then every 16. Candidate generation, routing, deadlines, elimination, and final
history refinements are unchanged.

Suggested first comparison: modes 0, 1, 3. Mode 2 separates the benefit of fitting
from the already-tested distribution change. Exact control expectations require
up to 256 cheap feature evaluations per candidate and synthetic query.

## Limits

Mode 1/4 correct the control's conditional mean; they do not make shuffled deck
states follow the real request process. All modes still use the original heuristic
elimination threshold and time-dependent sample count. Selection is performed on
the original simplified routing policy and before the winner-only history edits.
Improved statistical calibration therefore does not guarantee better real scores.

`selection_controls_test.cpp` is a small isolated test for all 255 nonempty
supports of an eight-product mock router, and for coefficient fitting/predictability.
It does not replace end-to-end score and legality checks.
