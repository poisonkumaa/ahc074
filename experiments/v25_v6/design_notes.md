# Final-stage exact demand objective

Source: `design_candidate.cpp`, generated by `design_make.py` from the frozen v25
`main_baseline.cpp`, SHA256
`A9E5CB6B45EE1562C60721BE09BDE2D0246AD8EEB95585C7721048D74143D7DA`.
The production `main.cpp` is unchanged. Both experimental control and treatment
enable the same x86 POPCNT pragma.

v25 estimates an exposed window's repair cost using the two color demands `z,o`.
Its anchor and joint-pair annealers periodically update linear marginal prices,
but the final support-aware anchor annealer keeps the last prices fixed. Its
relocations continue changing which products expose each window and the
anchor-dependent weights of those exposures.

This experiment changes only that last annealer's exposure-cost term. Define

`F(z,o) = 2*z*o/(z+o)`.

For each window, `z,o` start with the same four pseudocounts per color as v25.
Each exposed product contributes exactly the existing
`prices[anchor][window/8][1<<(window%8)]`. A paired sheet contributes each of its
two products separately. Moving one or exchanging two sheets recomputes their
contributions, then uses the exact nonlinear change in the sum of `F` values.
On rejection the maintained demand arrays are unchanged; on acceptance the
complete delta is applied once.

No additional factor `beta=.5` multiplies `F`: its derivative with respect to
zero demand is `2*(o/(z+o))^2`, exactly `.5` times the original `adjust_prices`
factor `4*p*p` when that routine's mix is one. The bank retrieval objective,
paired monochromatic-bank penalty, and support-gain model are retained. Earlier
anchor, matching, column, offspring, and candidate-selection searches are
unchanged.

Controls:

- `DESIGN_FLIP=0` (default): original final-stage exposure objective.
- `DESIGN_FLIP=1`: replace it with the nonlinear demand objective.
- Intermediate values blend the two exposure objectives.
- `DESIGN_FLIP_VERIFY=1`: on every valid proposal, recompute all item demands
  from scratch and compare them with the incremental objective. Any discrepancy
  beyond the floating-point tolerance aborts. This is a research validation
  setting, not a performance configuration.

Extra treatment work is `O(T)` arithmetic for each otherwise valid final-stage
proposal; that stage already updates support probabilities across 256 products.
No new time budget or iteration quota is added. `DESIGN_FLIP` logs proposals,
acceptances, initial/best objective, verified proposals, and maximum verification
error.

The nonlinear value is exact for this chosen demand model, not an exact
prediction of real routing cost. The actual router's main returns, donor choice,
and evolving bank orders can invalidate the model's independence assumptions.
Actual scores and runtime still determine whether to adopt the experiment.
