# Inherited six-core width40 child

Source `design_wide.cpp` is generated by `design_wide_make.py` from frozen v25
`main_baseline.cpp` SHA256
`A9E5CB6B45EE1562C60721BE09BDE2D0246AD8EEB95585C7721048D74143D7DA`.
Both experimental control and treatment enable the same POPCNT pragma.

The normal v25 pool already explores one B5 width37 root and B6 widths38/39,
then three anchor/matching replays and a crossover offspring. This experiment
offers a genuinely wider B6 map while retaining the established candidates:

- `CHILDMAP_WIDE=0` (default): original behavior.
- `CHILDMAP_WIDE=1`: retain the original seven candidates and try replacing only
  the optional crossover with a width40 child. If construction fails and at least
  .08 local layout-budget units remain, rebuild the original crossover instead.
- `CHILDMAP_WIDE=2`: build the original crossover first, then append the wider
  child as a ninth candidate if the existing budgets permit.

The parent is the original layout of the highest-width snapshot already selected
by the crossover code. The attempt requires B6 and parent width38 or39 so the
existing map-inheritance path can extend it to width40. Prefix columns moved into
the suffix and their comparison directions are selected by the existing inherited
map routine; all ordinary pairing, anchor, and feasibility construction remains.
The width40 attempt does not fall back to width38. This prevents spending its
remaining budget rebuilding a narrower family already represented in the pool.

The original absolute packing/layout deadlines are respected. No new runtime
allowance is added. The callback checks the packing deadline and .08 local units
of remaining layout budget before starting. `CHILDMAP_WIDE` logs parent width,
attempts, wider children built, ordinary crossover completion, and candidate count.

Construction can grow both `snapshots` and `candidates`. The wider parent's
`Design`, and the original crossover's `PackSnapshot` when needed for fallback,
are copied before those operations. Later callbacks refer to these owned copies,
not references potentially invalidated by vector growth.

A previous structural_v2 experiment with seven backing sheets worsened scores;
seven sheets also require additional changes to v25's B5/B6 exact metric and SIMD
generation assumptions. This experiment deliberately retains six backing sheets.
The width40 tradeoff is fewer prefix repair windows versus more crowded main-paper
banks and stronger core constraints. Its benefit requires measurement.
