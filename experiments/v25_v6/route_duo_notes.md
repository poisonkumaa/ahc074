# 2枚の既払いドナーによる操作列修復（不採用）

2026-11-06。凍結した v25 `main_baseline.cpp`（SHA256 `A9E5CB6B45EE1562C60721BE09BDE2D0246AD8EEB95585C7721048D74143D7DA`）を基にした実験。`main.cpp` は変更していない。

`nov5_relaxed_trace` の削除候補から、表示がまだ一致しない終端状態を最大2件保存する。既に操作列に登場する異なる2枚を選び、それぞれの最後の操作の挿入先を変更して、1枚では覆えない誤りを共同で修復する。候補の全操作を注文開始時から再実行し、各操作の可視性、予定した終端順序、表示、`rebuild_state` の再利用条件を満たす場合だけ評価する。未来の実注文は参照しない。

ソースは [route_duo.cpp](route_duo.cpp)、[route_duo.inc](route_duo.inc)、生成器は [route_duo_make.py](route_duo_make.py)。`NOV5_DUO=1` で有効、既定は無効。`NOV5_DUO_CPU` は累積 native clock 秒の上限、`NOV5_DUO_CHOICES` は候補紙数（既定6）。`NOV5_DUO_VERIFY=1` は別の素直な実装でも操作列を再検証する。

[duo_fixed_probe.json](duo_fixed_probe.json) と [duo_fixed_spec.json](duo_fixed_spec.json) の6ケース（0000–0005）は、保存済みの同一設計を使用。オンライン絶対期限は30 local units、`NOV5_RELAX_BUDGET=10` とした研究用比較であり、通常2秒の設計込み検証ではない。

| 設定 | 平均手数 | 基準との差 | エラー | helper内の改善回数 / 短縮手数（6件計） |
| --- | ---: | ---: | ---: | ---: |
| 無効 | 10621.6667 | 0 | 0 | 0 / 0 |
| 上限0.03秒 | 10621.6667 | 0 | 0 | 7 / 7 |
| 上限0.30秒 | 10621.6667 | 0 | 0 | 14 / 14 |
| 上限0.03秒＋独立再検証 | 10621.6667 | 0 | 0 | 7 / 7 |

全設定で、6件すべての標準出力が無効版とバイト単位で一致した。helper内の改善は外側の候補選択後の出力改善を意味しない。上限0.30秒の実測 helper CPU は1件0.1048–0.1351秒で、上限を使い切る前に探索が終わった。独立再検証は計8候補で完了し、可視性・表示の不一致はなかった。手数改善が確認できないため不採用。

高予算版でも、保存候補37,836件に対して2枚の被覆条件を満たした組は50組、完全な合法再実行は17件に限られた。この制限された近傍では、既払いドナー2枚による共同修復の機会が少なく、今回の実験では最終出力を改善できなかった。
